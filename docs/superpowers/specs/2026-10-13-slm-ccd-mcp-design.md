## 1. 意图、范围和成功标准

用户希望另一台局域网电脑的本地 Codex / Claude 等 MCP 客户端直接操作本机实验。首版成功标准是：远端能够查设备状态，加载 SLM 图片并调整位置 / 光栅，设置并读回 CCD 曝光，获取当前状态下的新图和原始数据；同时记录命令、参数、图案和采集身份。

首版支持 SLM1、SLM2、CCD 三个逻辑角色。未连接的角色标记为 unavailable，其余设备仍可独立使用。不从历史实验推断今天的设备编号、CCD 曝光或光路稳定状态。

首版提供单步联合加载采图，自动大规模扫描、优化闭环和浏览器控制台留待基本控制验收后扩展。首版包含必要的远端图片上传和结果下载，不包含任意脚本执行。

## 2. 方案比较与选择

| 方案 | 优点 | 代价 / 适用范围 |
|---|---|---|
| Python SDK + 网络 MCP（采用） | 直接复用厂家 Python / ctypes 能力，适合参数化调用和实验记录 | 需管理 Windows 投屏线程、相机回调和网络认证 |
| 远程桌面操纵厂家 GUI | 可迅速复用人工界面 | 依赖窗口位置和人工状态，不适合作为稳定 MCP 工具接口 |
| 控制 API + 网页控制台 + MCP | 提供连续可视操作面板 | 首版额外增加前端与预览服务，优先级低于基本控制 |

SDK 适配与 MCP 层分离，以便以后在相同协调层上增加脚本客户端或网页操作。

## 4. 组件与运行方式

```text
远端本地 MCP 客户端
        │ Streamable HTTP /mcp + Bearer
        ▼
MCP 工具与认证层 ────────────── 结果预览 / 文件下载
        │
        ▼
协调层：参数预检、全局操作锁、请求去重、状态版本、日志
        ├── SLM owner 专用线程：唯一 SDK 实例 + Win32 消息泵
        ├── CCD adapter：控制接口 + 帧回调 / 有界帧队列
        ├── 图像处理：输入检查、光栅、LUT、完整 panel 拼板
        └── 结果存储：RAW、预览、参数、操作记录
```

- 一个服务进程，单个 ASGI worker；项目级单实例锁防止重复启动。
- 所有 HDSLM 调用（包括枚举、open / show / close 和消息泵）在同一专用线程。
- CCD 回调只拉取和复制帧、发布帧 / 错误；不在回调内写盘、等待命令或修改曝光。
- 协调层串行执行设备修改及采图。联合操作期间阻止其他客户端插入调参。
- 服务必须运行在已登录 Windows 交互式桌面会话；不实现 Session 0 Windows 服务。
- 提供模拟模式和显式硬件模式。模块导入、配置验证及模拟服务不加载设备 DLL。
- MCP / HTTP 网关和设备 owner 生命周期独立于客户端连接；客户端退出不销毁投屏窗口。

预计代码按 `config`、`imaging`、`devices/slm`、`devices/camera`、`controller`、`storage`、`server` 分拆。厂家 Python 包装和 DLL 经配置的绝对路径加载，不复制进仓库。

## 5. 设备发现、绑定与状态

### 5.1 SLM

HDSLM 的 `SLM_Disp_Info_NumberName*` 会关闭其已打开投屏窗口。启动设备 owner 时，在没有本进程投屏窗口的条件下枚举一次，随后缓存 index、名称、SN、桌面坐标和分辨率。

配置中每个角色记录期望身份、桌面矩形及位深。由于历史 SN 重复，须联合匹配 SN / 名称、矩形和尺寸，且两角色不能映射到同一个显示器。初次探测输出候选列表，用户核验物理角色后保存本机绑定配置；普通桌面显示器不凭尺寸自动认作 SLM。

SLM1 缺席时保留逻辑角色但不打开窗口。热插拔 / 显示拓扑改变时，角色变为需重新绑定；停止依赖该角色的命令，不自动换绑另一显示器。重新探测只能在设备 owner 关闭后显式进行。

普通状态工具读取缓存及 owner 提供的窗口健康信息，不调用枚举函数。窗口信息至少含 alive、hung、visible、minimized、矩形和遮挡检查时间；这些状态不声明液晶像素物理读回。

### 5.2 CCD

枚举后按保存的 camera ID 绑定。首次只有一台且型号匹配时可选择该设备；出现多台时需明确 ID，不任取第一台。打开后保存原始设置、格式及取值范围，后续显式启动 RAW 流。

相机忙或断连返回明确错误。服务不自动关闭 ToupView / MagicHolo 等其他应用。状态记录已打开 / streaming / disconnected / error 及最近核验的设置时间。

### 5.3 状态与版本

设备状态含角色、连接状态、绑定证据、图案 hash / 位深 / 放置、光栅配置、相机读回及 `state_version`。每次成功修改递增版本；修改工具可传入期望版本，冲突在硬件执行前拒绝。查询缓存时附带采样时间和缓存年龄。

## 6. SLM 图像、位置与光栅

### 6.1 输入

- 接受 NPY（禁止 pickle）、灰度 PNG / BMP。
- uint8 只表示 0..255 的 8bit；uint16 只表示 0..1023 的 native10。
- SLM1 默认 8bit，拒绝 10bit。SLM2 默认 native10；显式声明 8bit 时可以原码加载，不自动乘 4。
- RGB10 厂家打包文件须显式指定格式并严格校验位布局；普通彩色图不自动转灰度。
- 不自动缩放、插值、旋转、镜像、裁切或逐图亮度归一化。
- 图片文件可来自允许的本机输入目录，或远端分块上传为 asset ID。

### 6.2 放置

小图相对面板居中后增加 `offset_x_px` / `offset_y_px`，x 随列向右，y 随行向下。SLM2 当前默认 (+10,+61)。1920×1200 面板上的 1000×1000 小图左上角为 (470,161)。SLM1 默认 (0,0)。

完整面板输入必须声明 `placement=panel`，不再应用小图偏移。小图声明 `placement=centered`，越界拒绝，保留旧已显示状态。背景码单独配置，SLM2 默认为 0；SLM1 默认背景亦为 0，历史 64 仅是可选择的实验预设。

面板由软件拼成原生数组并调用 `SLM_Disp_Data`；SDK offset 固定为 0，SDK 附加相位关闭，避免双重放置 / 双重光栅。更改位置时从保留的原始 asset 重新生成并投屏，不累计移动已拼好的 panel。

### 6.3 相位屏光栅

使用有符号空间频率 `(fx,fy)`，单位 cycle/pixel：

`phi_g = 2*pi*(fx*x + fy*y) + phi0`。

x / y 是输入图内以 `floor(width/2)` / `floor(height/2)` 为原点的列 / 行坐标，光栅随小图移动，背景区域不附加载波。频率均限制在 [-0.5,+0.5]，默认 (0,0)；光栅参数为绝对配置，每次从基图重算，重复调用不累计叠加。

支持两种明确标注的合成：

1. `code`：对基图码加入量化线性斜坡后按 256 / 1024 取模。输出明确标为码域、未标定物理相位；不默认承诺完整 2π 响应。
2. `lut`：需要显式指定长度匹配、有限实数的 code→phase LUT；基图码先查相位，与载波相加后按圆周距离选择最近码，平局取较小码。没有 LUT 时不接受该模式。

已有载频图默认不附加新光栅。工具返回实际频率、量化方式和输出 hash。相位光栅导致的真实 CCD 移动方向和幅度用实拍校验，不由图像坐标直接推定机械方向。

### 6.4 振幅屏光栅

独立生成 uint8 振幅光栅，支持 binary / sinusoidal、周期 / 方向或 `(fx,fy)`、暗亮码和 binary duty cycle。它可以作为新 asset 加载和移动。

首版不对任意已有振幅全息灰度图做相位取模相加，也不猜测其复杂场编码重新改变载频。已有振幅全息图的载频调整由外部生成器重生成后上传；需要通用复场振幅编码时另行扩展。

## 7. CCD 参数、采图与预览

- `exposure_us` 使用整数微秒；`gain_percent` 使用 SDK 单位，均查询实际支持范围。
- 修改曝光 / 增益前预检；设置后读回。显式曝光默认先关闭自动曝光；单独开启 AE 时保留实际读回和模式。
- RAW 流要求单色 YYYY，有效位深由 SDK 读回；uint16 保存不声称 16 有效位。
- 默认软件 ROI，全幅 sensor 坐标 `(x,y,width,height)`；不改变硬件分辨率，不翻转 RAW 行。
- 普通采图默认 1 张，可指定 1..16 张；保存单张 RAW，不把平均结果当单帧。额外平均预览需要声明帧数。
- 联合操作的默认稳定等待为最后图案 / 参数更新后 0.3 s，再加一个实际曝光间隔，随后丢弃 3 张新完成帧后保留目标帧。
- 稳定等待 / 丢帧数显式可配置并保存。该策略是保守软件时序，不声明外触发同步或精确曝光起点。
- 一次 capture 的超时上限默认 120 s，可配置；执行前根据曝光、等待及帧数估计最低预算，不接受明显无法完成的请求。
- 保存 SDK 帧号、有效 timestamp / exposure 字段、主机单调时间、更新阈值和丢弃帧身份；缺失字段保持缺失，不造精确时间。
- PNG 预览默认以有效位深固定映射至 8bit、长边不超过 1024；可显式选择固定黑白显示范围。显示范围和缩略规则保存在元数据中。
- 同时返回 min / max、均值、接近满量程比例等原始统计，便于远端调整曝光。

## 8. MCP 工具与资源

工具名在实施中保持以下职责和参数语义，可按官方 SDK 要求细化类型。

| 工具 | 主要输入 | 返回 / 行为 |
|---|---|---|
| `lab_status` | 无 | 缓存设备状态、版本、最近错误 |
| `lab_connect` / `lab_disconnect` | 可选角色列表 | 显式打开 / 释放；缺席角色返回独立结果 |
| `asset_list` | 允许的输入集合 | 可用 asset 元数据，不遍历任意目录 |
| `asset_upload_begin/chunk/finish` | 文件名、长度、SHA256、分块数据 | 校验后发布不可变 asset ID |
| `slm_load_image` | 角色、asset ID / 允许路径、位深、placement、可选偏移 | 输出 panel 信息与 hash |
| `slm_set_offset` | 角色、x/y 像素偏移 | 有已加载小图时重算投屏；panel 模式拒绝偏移 |
| `slm_set_grating` | SLM2、fx/fy、phi0、mode、可选 LUT ID | 更新绝对附加光栅并重算投屏 |
| `slm_make_amplitude_grating` | 尺寸、频率、样式、码值、duty | 生成 SLM1 uint8 asset，不自动投屏 |
| `slm_show_uniform` | 角色、位深、gray | 全 panel 均匀码；不声称遮光 |
| `slm_restore` | 角色、已注册 restore asset | 加载显式恢复图；无 restore 时返回错误 |
| `ccd_get_settings` | 无 | 当前格式、范围、曝光、增益、AE |
| `ccd_set_settings` | 可选曝光 / 增益 / AE | 返回实际读回及版本 |
| `ccd_capture` | 帧数、可选 ROI、等待 / 丢帧数、超时 | 新 RAW 记录、预览、统计、下载引用 |
| `lab_load_and_capture` | 一至两屏 load 配置及可选 CCD 设置、capture 配置 | 全局锁内完整加载采图结果 |
| `operation_get` | operation ID | 已执行结果或执行状态不确定 |

联合操作顺序：所有 asset / panel / CCD 参数预检 → 应用相机设置 → SLM2 show（如指定）→ SLM1 show（如指定）→ 等待与新帧处理 → 保存结果。未指定角色保持当前状态。指定缺席设备时预检失败，不先修改其他设备。

预览和参数作为 MCP 资源 / ImageContent 返回；RAW 使用受认证 HTTP 下载，不直接放入模型文本上下文。MCP 工具声明正确的只读 / 修改注解，业务层仍自行校验权限和参数。

## 9. 并发、请求去重和异常

- 硬件修改 / capture 使用统一锁；状态缓存读取不等待长采图结束。
- 每个修改操作有 operation ID 和规范化参数 hash。客户端可指定 UUID 便于重发查询；不指定则生成并返回。
- SQLite 操作记录在硬件前写入 intent；完成后写结果和阶段。相同 ID / 相同参数重发返回原结果；同 ID / 不同参数拒绝。
- 已记录 intent 但没有可靠完成结果的操作标记 uncertain，不自动重做。离线存储失败在硬件前拒绝；硬件后保存失败返回硬件是否已提交的阶段信息。
- 参数越界和数据格式错误在 SDK 调用前返回 validation error。
- DLL 错误、窗口失效、CCD 断连、超时和保存失败分开报告，不无限重试硬件命令。
- 中途失败保留已得到的 RAW 和 partial manifest。联合操作不承诺硬件原子回滚，失败结果列出已完成步骤。
- 客户端断开不代表硬件取消。正在运行的操作完成并落盘，客户端用 operation ID 查询。
- 正常关闭尝试 Stop / 恢复相机打开前设置 / Close；逐项保存失败。SLM 仅有显式注册恢复图时尝试恢复，最后关闭本进程窗口，不承诺关闭后图像留存。
- Native DLL 导致进程终止时，旧操作保持 uncertain；服务不自动重启后重新执行命令。

## 10. 文件与网络边界

### 10.1 文件

本机输入目录由配置 allowlist 指定，初始仅项目 `assets/`；用户可显式增加历史实验加载目录。解析后的绝对路径须在允许根内，并检查 Windows junction / symlink 等最终目标；不开放任意磁盘访问。

上传每块解码后不超过 1 MiB，总长度默认不超过 32 MiB；验证扩展名、实际数组维度 / 大小、位深和 SHA256。finish 前文件位于临时区，成功后作为不可变 asset 发布；失败和过期上传只清理本项目临时区。

采集结果位于 `runtime/captures/<capture_id>/`，包含 RAW NPY、预览 PNG、manifest JSON。完整 RAW 帧约 48.8 MB，以流式认证下载提供。下载通过 capture / file ID 精确定位已登记结果，拒绝路径穿越；不在 URL 放令牌。

操作 SQLite / JSONL 位于 `runtime/`；日志不记录令牌或上传 base64。磁盘容量不足时预检拒绝新采集；不会自动删除历史 RAW。

### 10.2 网络与客户端

采用官方 MCP SDK Streamable HTTP。端口默认规划 8765，监听地址通过配置明确指定；本机模拟验证绑定 127.0.0.1，局域网运行绑定选定的实验电脑私网接口。

`/mcp` 与文件下载同受 Bearer 令牌认证，配置 Host / Origin allowlist。令牌来自环境变量 / 本机私有配置，不写入 README、Git 或结果清单。提供局域网受限防火墙设置步骤，不默认开放公网或所有网络 profile。

Codex 类可接受 HTTP URL / header 的客户端使用直接连接；只支持 stdio 接入的本地客户端使用标准远程 MCP 桥接命令。具体客户端语法在实施时按其官方文档核验并提供模板，不假设不同客户端配置格式相同。直接 URL / 桥接均不要求将实验电脑暴露到互联网。

本首版采用静态 Bearer，未实现 OAuth 登录流程。要求浏览器 OAuth 的云端 connector 不属于已确认的本地局域网客户端验收范围。可信私网初始使用 HTTP；需要加密的网络环境配置 HTTPS 入口，客户端信任相应证书。

## 11. 验证与验收

1. **无设备模拟验证**：验证输入类型 / 值域、当前偏移 (470,161)、越界、panel 无二次偏移、载波绝对重算、LUT 圆周映射、振幅光栅、请求去重与联合命令不交错。
2. **MCP 协议验证**：真实 SDK client 连接模拟服务，执行工具发现、参数校验、上传、load / capture、ImageContent、资源 / 认证下载；拒绝无令牌、错误 Host / Origin 和非法路径。
3. **设备探测与绑定**：核验当前 SLM2 / CCD，记录候选、身份和范围；SLM1 标记缺席。检查厂家应用占用后再联调。
4. **当前硬件小范围联调**：加载用户选定已知图，核验像素偏移；小幅光栅调整并采新图；设置一次明确曝光并读回；保存全幅 RAW / ROI / 元数据，检查新帧身份与预览。
5. **局域网验收**：另一台电脑实际调用 MCP 并看到新预览，下载与本机 SHA256 一致的 RAW。无法接触远端时保留可执行验收步骤和本机协议证据，明确远端验收待完成。
6. **SLM1 接入验收**：插入后关闭设备 owner、重新探测绑定，再验证 8bit 图和独立振幅光栅；此前不声称已完成双屏实测。
